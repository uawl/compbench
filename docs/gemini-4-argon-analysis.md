# Gemini 4 Argon 코드 생성 분석

> 본문의 8개 문제 분석과 재현 스크립트는 `v1/benchmarks/suite-original.tsv`를 사용한다. 현재 정규 `suite.tsv`는 26개 문제다.

> 이 문서의 측정값은 버전 분리 전 하네스에서 얻은 기록이다. 재현 명령은 분리된 v1의 정수 AST·2인자 ABI를 사용한다. 당시 측정 루프에는 arena 초기화가 포함되어 있었으므로 새 측정값과 혼합하지 않는다.

Argon은 v1 문제 8개를 모두 통과했고, 이번 재측정에서 스칼라 베이스라인 대비 기하평균 10.12배였다. exp-a는 9.84배, Astra max는 5.98배였다. 제출물의 호출 시간을 직접 비교하면 Argon이 exp-a보다 기하평균 약 2.6%, Astra max보다 약 69% 빠르다. exp-a와의 전체 차이는 작고, 문제별로 강점이 다르다. 이 한 번의 순차 측정으로 통계적인 우위를 주장하지 않는다.

원본 3개와 Argon의 최적화 제거 버전 4개를 같은 v1 스칼라 문제군에서 순차 실행했다. 현재 하네스의 CPU affinity, 7회 중앙값, 교대 베이스라인 측정을 사용했다. 원본 소스는 수정하지 않았고 실행 전후 해시가 같았다.

| 문제 | Argon | exp-a | Astra max | Argon / exp-a 상대 속도 |
| --- | ---: | ---: | ---: | ---: |
| 합계 | 0.523 µs | 0.527 µs | 0.858 µs | 1.01배 |
| unsigned 최댓값 | 1.321 µs | 1.425 µs | 8.515 µs | 1.08배 |
| 조건부 합계 | 3.316 µs | 2.544 µs | 4.852 µs | 0.77배 |
| 몫·나머지 | 123.218 µs | 123.737 µs | 123.218 µs | 1.00배 |
| 상호 재귀 | 5.105 µs | 6.032 µs | 6.072 µs | 1.18배 |
| helper mix | 13.218 µs | 12.591 µs | 15.754 µs | 0.95배 |
| 비꼬리 합계 | 6.5 ns | 6.8 ns | 10.3 ns | 1.05배 |
| 피보나치 | 83.1 ns | 103.5 ns | 161.9 ns | 1.25배 |

상대 속도는 비교 대상 시간 / Argon 시간이다. 1보다 크면 Argon이 빠르다. 작은 차이는 측정 잡음의 영향을 받는다.

## 구현 구조

Argon은 AST를 별도 IR로 옮기고 다음 최적화를 적용한다.

- 호출 그래프를 이용해 작은 함수를 3회에 걸쳐 인라이닝한다. 직접 자기 재귀는 펼치지 않고, 함수 순서 조건을 만족하는 작은 상호 재귀 함수는 펼친다.
- 상수 폴딩, 대수적 단순화, let 상수 대입·제거·분기 안으로 이동을 수행한다.
- 결합법칙이 성립하는 비꼬리 재귀에 숨은 누산기를 추가한다. 함수 번호는 유지하며 정상 호출 때 누산기를 초기화하고 자기 꼬리 점프에서는 보존한다.
- 연속 배열 순회와 add/xor/or/and/mul/max/min 누산 패턴을 찾아 AVX2 루프 또는 스칼라 4회 언롤을 생성한다.
- 일반 호출이 없는 함수는 로컬 8개까지 레지스터에 유지한다. 자기 꼬리 호출 인자는 의존성을 분석해 가능한 갱신을 직접 수행하고, 순환 의존성에는 XMM·스택 임시값을 쓴다.

따라서 성능은 벡터화와 재귀·스칼라 코드 생성의 효과가 함께 만든다.

## 최적화를 끈 실험

모든 변형이 원래 8개 문제의 정확성 검사를 통과했다. `SIMD 제거`는 벡터 경로를 스칼라 4회 언롤로 바꾸고, `빠른 루프 제거`는 벡터화와 언롤 경로를 모두 생략한다. 후자는 기존 레지스터·스택 프레임 배치를 유지하므로 완전히 새로 설계한 스칼라 컴파일러와 같지는 않다.

| 문제 | Argon 원본 | SIMD 제거 | 빠른 루프 제거 | 누산기 변환 제거 | 상호 재귀 인라이닝 제거 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 합계 | 0.523 µs | 2.659 µs | 6.102 µs | 0.536 µs | 0.521 µs |
| 최댓값 | 1.321 µs | 5.632 µs | 8.147 µs | 1.321 µs | 1.294 µs |
| 조건부 합계 | 3.316 µs | 13.953 µs | 16.449 µs | 3.329 µs | 3.329 µs |
| 상호 재귀 | 5.105 µs | 5.120 µs | 5.038 µs | 5.021 µs | 14.351 µs |
| helper mix | 13.218 µs | **7.448 µs** | 10.194 µs | 13.215 µs | 13.163 µs |
| 비꼬리 합계 | 6.5 ns | 13.2 ns | 28.0 ns | 66.5 ns | 6.4 ns |
| 피보나치 | 83.1 ns | 82.2 ns | 81.2 ns | 98.8 ns | 82.8 ns |

합계·최댓값·조건부 합계에는 SIMD의 뚜렷한 이득이 있다. 상호 재귀에는 인라이닝 효과가 있고, 비꼬리 합계에는 누산기 변환과 그 뒤의 벡터화가 큰 효과를 낸다. 각 변형은 서로 독립적인 실험이라 효과를 더하거나 곱해 전체 기여율로 해석하지 않는다.

## helper mix: 벡터화가 오히려 손해

Argon의 가장 큰 약점이다. SIMD를 끄면 13.22 µs에서 7.45 µs로 줄어 약 1.77배 빨라진다. 이 스칼라 버전은 exp-a의 12.59 µs보다도 빠르다.

벡터 표현식 생성기 `emit_avx2_expr()`는 let 변수 참조를 만나면 값의 표현식을 다시 생성한다. `y = (x ^ (x >> 33)) * C`를 계산한 뒤 `y ^ (y >> 33)`를 만들 때 곱셈을 다시 수행한다. 합계와 XOR 누산기도 같은 map 결과를 각각 계산한다. 8원소 주 반복문에는 `vpmuludq`가 24개 있으며, 곱셈 상수의 broadcast와 배열 읽기도 반복된다. AVX2의 64비트 하위 곱셈은 여러 32비트 부분 곱으로 구성된다.

스칼라 언롤 버전은 let의 중간값과 최종 mix 값을 레지스터에 보존한다. 한 원소에 `imulq` 한 번을 수행하고 결과를 합계·XOR에 함께 사용한다. 누산기와 인덱스도 직접 갱신해 exp-a에서 보이는 임시 스택 저장을 줄인다.

Argon의 벡터 코드에는 Astra max의 벡터 스택 spill 문제가 보이지 않지만, 표현식 재사용이 없어 계산량이 커진다. SIMD 적용 여부를 판단하는 비용 모델과 벡터 let 값의 재사용이 개선 후보다.

## 조건부 합계: 더 많이 언롤해도 조건 재사용에서 밀림

Argon은 8원소를 두 누산기 묶음으로 처리하지만 exp-a는 4원소를 처리한다. 그럼에도 exp-a가 약 1.30배 빠르다.

Argon은 `(x & 3) == 0`을 합계와 개수의 누산기에서 각각 계산하고, 조건 선택을 위해 boolean을 다시 마스크로 변환한다. 상수 3의 broadcast도 각 표현식에서 반복한다. exp-a는 조건을 `%ymm8`에 보존해 두 누산기에 재사용한다. 원소당 중복 작업의 차이가 실제 생성 코드에 있다. 중복 제거만 따로 적용한 실험은 하지 않았으므로 이것이 차이의 전부라고 단정하지 않는다.

Argon의 도달 가능한 YMM 명령은 75개, exp-a는 22개지만 이 정적 개수를 속도 비율로 해석하면 안 된다. Argon에는 8원소 주 루프와 별도 4원소 잔여 루프가 함께 있다.

## 합계와 최댓값

합계는 Argon과 exp-a 모두 8원소를 독립적인 두 벡터 누산기로 처리하고 루프 끝 인덱스를 레지스터에 둔다. 약 0.52 µs로 비슷하다.

Argon도 `RED_MAX`·`RED_MIN`을 인식한다. unsigned 최댓값은 부호 비트 XOR와 signed 벡터 비교로 구하며 8원소를 처리한다. Astra max는 이 누산 패턴을 인식하지 못해 스칼라로 처리한다. 이것이 Astra max 대비 약 6.45배 차이를 설명하는 가장 큰 구조적 차이다.

Argon의 max SIMD는 각 결합 때 부호 변환·마스크 선택을 수행하고 exp-a와 코드 구성이 다르다. 이번 1.32 µs 대 1.42 µs 차이에서 특정 명령의 기여를 분리하지는 않았다.

## 상호 재귀와 비꼬리 합계

상호 재귀는 Argon·exp-a·Astra max 모두 두 단계를 인라이닝해 자기 반복문으로 만든다. Argon은 SIMD 없이 약 5.10 µs로 exp-a의 6.03 µs보다 빠르다. Argon의 실제 출력은 배열 읽기 뒤 누산기와 인자를 직접 갱신하며, exp-a의 여러 임시 복사·무조건 점프와 차이가 있다. 인라이닝을 끄면 14.35 µs가 되므로 반복문으로 합치는 효과는 확인된다. 이미 인라이닝한 두 구현 사이의 나머지 격차는 스칼라 생성 코드 차이이며, 개별 명령별 기여까지 측정하지는 않았다.

비꼬리 합계는 숨은 누산기를 추가한 뒤 벡터화한다. Argon은 기존 함수에 누산기를 붙여 전체 32원소를 인덱스 0부터 처리한다. exp-a는 추가 내부 함수로 변환하지만 두 구현의 시간은 6.5–6.8 ns로 비슷하다. Astra max의 첫 원소 인라이닝과 잔여 스칼라 처리는 [이전 비교](astra-max-vs-exp-a.md)에 설명되어 있다. Argon의 누산기 변환을 끄면 66.5 ns로 느려지고 YMM 경로도 사라진다.

## 피보나치: 계산 복잡도는 유지하며 호출 비용을 줄임

Argon의 결합 연산 재귀 변환은 피보나치에도 적용된다. 생성 코드는 `fib(n-2)`를 정상 재귀 호출하고 결과를 누산기에 더한 다음 `n -= 1`로 자기 반복문을 돈다. exp-a는 반대로 `fib(n-1)`을 호출하고 `n -= 2`로 반복한다. 둘 다 메모이제이션이나 동적 계획법을 사용하지 않으며 지수적인 계산 복잡도는 유지된다.

Argon에서 누산기 변환을 끄면 두 정상 재귀 호출과 스택의 중간 결과 저장이 돌아온다. 이번 측정은 83.1 ns에서 98.8 ns로 느려져 약 1.19배의 변환 효과가 있었다. Argon과 exp-a의 1.25배 차이는 반복문의 구성과 callee-saved 레지스터·프레임 비용이 함께 다르므로 재귀 분기 선택 하나의 효과로 단정하지 않는다.

몫·나머지는 세 구현 모두 가변 `divq`가 남고 약 123 µs로 비슷하다.

## 상수 폴딩과 정확성 확인

Argon은 `eval_const(e->op, ...)`를 수행한 **뒤** `e->op = CB_CONST`로 바꾼다. exp-a에서 발견했던 연산 종류를 먼저 덮어쓰는 오류는 없다.

별도 12개 진단 프로그램, 총 4,704개 입력 검사를 통과했다. `2 + 3`, u64 뺄셈·곱셈의 wraparound, unsigned 비교, shift의 63 마스크, 중첩 상수식과 let 상수 대입을 확인했다. 나누기·mod 0은 상수식과 런타임 입력에서 모두 확인했고, `x / x`는 x=0일 때 0을 유지했다. 이 진단 프로그램의 성능은 원래 8개 문제 점수에 포함하지 않았다.

여기서 확인한 범위는 v1의 스칼라 AST다. 리스트가 추가된 현재 문제군에 대한 검증 결과는 아니다.

## 재현 및 산출물

```sh
make v1
python3 scripts/analyze_v1_argon.py
python3 scripts/render_results.py --analysis build/analysis/v1-argon/summary.json \
  --output-dir build/figures/v1-argon --formats png svg pdf
```

`build/analysis/v1-argon/summary.json`에 원본 해시, 문제별 시간과 직접 상대 배율, 모든 변형의 정확성 결과·어셈블리 통계, 추가 진단 결과가 있다. 각 하위 디렉터리에 분석용 C 소스·컴파일 로그·실행 파일·문제별 어셈블리를 보존했다. 그래프의 모델 비교는 기존 평가 JSON을, 최적화 분석은 이번 순차 실험 JSON을 사용한다.
