# Astra max와 Gemini exp-a 비교

> 이 문서의 측정값은 버전 분리 전 하네스에서 얻은 기록이다. 재현 명령은 분리된 v1의 정수 AST·2인자 ABI를 사용한다. 당시 측정 루프에는 arena 초기화가 포함되어 있었으므로 새 측정값과 혼합하지 않는다.

두 코드 모두 스칼라 베이스라인을 크게 개선하지만, 격차는 최댓값의 벡터화 지원 여부와 생성 코드의 비용에서 나온다. 상호 재귀·비꼬리 재귀를 다루는 구조 변환은 Astra max도 수행한다. 해당 최적화가 없었던 Astra high와는 구분해야 한다.

원본 소스를 수정하지 않고 분석용 복사본을 빌드해 동일한 v1 문제 8개를 순차 평가했다. 각 실험 변형도 기본 정확성 검사를 모두 통과했다. 베이스라인은 보존된 v1 스칼라 코드 생성기이며, 현재 하네스의 7회 중앙값을 사용했다. 기하평균 배율은 Astra max 5.98배, exp-a 9.86배였다. 두 제출물의 호출 시간을 직접 비교한 기하평균으로 exp-a가 약 1.63배 빠르다. 수치는 이번 실행 기준이며 작은 차이는 측정 잡음의 영향을 받는다.

| 문제 | Astra max | exp-a | exp-a 상대 속도 | Astra max / exp-a SIMD |
| --- | ---: | ---: | ---: | --- |
| 합계 | 0.842 µs | 0.528 µs | 1.59배 | 사용 / 사용 |
| unsigned 최댓값 | 8.746 µs | 1.455 µs | 6.01배 | 없음 / 사용 |
| 조건부 합계 | 5.224 µs | 2.583 µs | 2.02배 | 사용 / 사용 |
| 몫·나머지 | 124.239 µs | 125.891 µs | 0.99배 | 없음 / 없음 |
| 상호 재귀 | 6.155 µs | 6.167 µs | 1.00배 | 없음 / 없음 |
| helper mix | 14.716 µs | 12.912 µs | 1.14배 | 사용 / 없음 |
| 비꼬리 합계 | 10.8 ns | 7.0 ns | 1.54배 | 사용 / 사용 |
| 피보나치 | 161.0 ns | 108.4 ns | 1.49배 | 없음 / 없음 |

SIMD 여부는 진입점에서 도달 가능한 생성 어셈블리의 YMM 명령으로 판별했다. 다른 제출물의 점수나 서로 다른 문제군을 이 표에 섞지 않았다.

## 가장 큰 격차: 최댓값 누산 패턴

Astra max의 `cg_find_loop()`는 누산기 갱신의 최상위 연산이 `add`, `mul`, `and`, `or`, `xor`인 경우를 요구한다. `(if (gt x acc) x acc)`는 `CB_IF`여서 거절한다. 벡터 비교와 조건 선택 코드는 구현되어 있지만 최댓값 누산을 하나의 reduction으로 인식하지 못한다.

exp-a의 `match_acc_update()`는 비교 방향과 분기의 누산기 참조를 확인해 `RED_MAX`와 `RED_MIN`을 따로 판별한다. unsigned 값을 최상위 비트 XOR로 변환한 뒤 signed 벡터 비교로 처리하고 마지막에 수평 최댓값을 구한다. Astra max의 실제 출력은 원소별 비교·분기이고 exp-a는 8원소를 처리하는 벡터 루프다. 이것이 약 6배 차이의 직접적인 구조적 원인이다.

## 둘 다 벡터화하지만 합계 루프의 비용이 다름

Astra max는 4원소당 한 벡터 누산기에 `vpaddq`를 수행한다. 매 반복에 스택에 저장된 끝 인덱스를 읽고, 남은 개수를 다시 계산한다. 현재 합계에서 사용하지 않는 벡터 인덱스도 매 반복 증가시킨다.

exp-a는 8원소를 두 벡터 누산기에 나누어 더하고 마지막에 합친다. 끝 인덱스를 레지스터에 유지하고 직접 비교한다. 서로 독립적인 두 누산기로 한 누산기에 계속 의존하는 구조도 줄인다. 생성된 반복문에 이러한 차이가 있으며 이번 측정에서 exp-a가 약 1.59배 빠르다. 개별 명령 비용의 기여율까지 따로 측정하지는 않았다.

## 조건부 합계: 중복 계산과 벡터 임시값 저장

두 구현 모두 4원소 단위로 벡터화한다. 따라서 약 2배 차이를 벡터 폭으로 설명할 수 없다.

Astra max는 조건 선택을 일반적인 마스크 경로로 처리한다. 활성 마스크·조건·분기 결과를 스택에 저장하고 다시 읽는다. 조건부 원소 읽기는 `vpmaskmovq`로 수행한다. 합계와 개수의 두 누산기를 각각 생성하며 `(x & 3) == 0` 조건을 다시 계산한다.

exp-a는 같은 조건을 `%ymm8`에 유지해 두 누산기에서 재사용한다. 연속 접근의 유효 범위를 루프 전에 확인하고 직접 벡터 읽기와 레지스터의 비트 선택으로 결과를 만든다. 벡터 임시값을 스택에 저장하지 않는다. 도달 가능한 코드의 YMM 명령도 Astra max 39개, exp-a 22개로 달랐다. 이 숫자는 정적 명령 개수이며 동적 실행 횟수나 사이클 수는 아니다.

## helper mix: 벡터화만으로는 빨라지지 않음

Astra max의 벡터 루프는 같은 mix 표현식을 합계·XOR 누산기에서 각각 계산한다. 각 계산에는 여러 벡터 스택 저장·읽기와 64비트 곱셈을 구성하는 부분 곱 연산이 있다. 이 두 map 결과 사이에서 표현식 값을 공유하지 않는다.

exp-a는 SIMD를 사용하지 않는다. 한 원소의 mix 결과를 구해 두 누산기에 사용하고 스칼라 반복문을 4회 언롤한다. 일부 곱셈 식을 중복 생성하는 단점도 있지만, 이 문제에서는 전체 루프가 더 빠르다.

분석용 복사본에서 확인한 시간:

| 변형 | helper mix 시간 |
| --- | ---: |
| Astra max 원본 | 14.72 µs |
| Astra max 벡터 경로 제거 | 14.64 µs |
| exp-a 원본 | 12.91 µs |
| exp-a 스칼라 언롤 제거 | 16.57 µs |

Astra max는 이 문제에서 벡터화의 뚜렷한 이득이 없었고 exp-a에는 스칼라 언롤의 이득이 있었다. exp-a가 이 문제에서 벡터화했다고 해석하면 안 된다.

## 비꼬리 합계: 둘 다 변환하지만 진입부 인라이닝이 다름

Astra max도 `cg_reduce_recursion()`으로 숨은 누산기를 추가해 비꼬리 합계를 반복문으로 바꾸고 벡터화한다. 고급 재귀 변환의 유무로 두 구현을 구분할 수는 없다.

다만 Astra max는 `main`에서 작은 재귀 함수의 첫 단계를 인라이닝한다. 원소 0을 읽고 그 값을 보존한 채 변환된 나머지 합계 함수를 호출한다. 길이 32에서는 인덱스 1부터 벡터 처리해 끝에 스칼라 원소 3개가 남는다. exp-a는 전체 32원소를 인덱스 0부터 벡터 처리한다.

Astra max에서 진입 함수의 인라이닝만 끄면 10.8 ns에서 7.9 ns로 줄어 exp-a의 7.0 ns에 가까워졌다. 이 인라이닝 제거는 모든 문제를 개선하지는 않았다. 합계 같은 다른 문제의 결과는 반대 방향도 나타났으므로 첫 단계 인라이닝이 항상 나쁘다고 일반화하지 않는다.

## 피보나치와 거의 차이가 없는 문제

피보나치에서 Astra max는 두 재귀 호출을 유지하고 첫 결과와 호출 인자를 스택 임시값으로 보존한다. exp-a는 첫 결과를 callee-saved 레지스터에 유지하며 한 재귀 분기를 반복문으로 변환한다. 그러나 exp-a에서 그 반복문 변환을 끈 실험은 이 입력에서 느려지지 않았다. 따라서 약 1.49배의 차이를 재귀 변환 하나의 효과로 단정할 수 없고 일반적인 스칼라 호출·임시값 처리 비용도 함께 봐야 한다. 둘 다 메모이제이션이나 동적 계획법으로 바꾸지는 않는다.

상호 재귀는 두 구현 모두 작은 함수들을 인라이닝해 두 단계를 같은 자기 반복문에서 수행한다. 약 6.16 µs로 차이가 없었다. 가변 나눗셈·나머지도 두 구현 모두 SIMD 없이 `divq`로 처리해 약 124–126 µs로 비슷했다.

## 해석과 재현

격차를 줄이는 데 가장 직접적인 항목은 최댓값 reduction 인식, 조건식·map 결과의 재사용, 벡터 임시값의 레지스터 유지, 루프 불변값 유지와 언롤 구성이다. 이미 둘 다 가능한 재귀 변환을 추가하는 것보다 이번 문제군에서는 이러한 생성 코드의 차이가 중요했다.

```sh
make v1
python3 scripts/compare_v1_max.py
```

`build/analysis/v1-max/summary.json`에 원본 해시, 문제별 시간·상대 배율·도달 가능한 어셈블리 통계와 6개 실험 버전의 결과가 있다. 하위 디렉터리에는 분석용 소스, 실행 파일과 문제별 어셈블리를 보존했다. `res/v1`은 수정하지 않았다.

exp-a의 상수 폴딩 오류가 원래 8개 문제의 성능을 오염시키지 않았다는 확인은 `docs/v1-codegen-analysis.md`에 있다. 이번 비교는 같은 8개 문제의 결과이며 일반적인 AST 전체에 대한 정확성을 보증하지는 않는다.
