# Argon high 최적화와 추가 벤치마크

대상은 v1 제출물 `res/v1/gemini-4-argon-high.c`이며 SHA-256은 `2ba654ddb3dd5b6b6460d1e422235370075c8fc80a1f353bc386fa51ccbc0735`다. v2의 `gemini-4-argon.c`나 기존 Argon medium/exp와는 별개다.

이 컴파일러는 정수 누산의 AVX2 벡터화, 상수 나눗셈, 인라이닝, 공통식 제거와 비꼬리 재귀 변환을 구현했다. 그러나 일부 벡터 코드와 꼬리 호출 인자 갱신이 잘못되어 **확장 문제군은 20/26 통과**다. 실패한 문제를 1.0으로 반영하는 새 규칙으로 기존 측정값을 재계산한 전체 점수는 **7.129539배**다. 새 문제 18개 중 13개를 통과했고, 원래 문제 8개 중에는 `divmod`가 실패한다. 틀린 결과나 시간 초과는 배율 1.0으로 반영한다.

## 실제로 구현된 최적화

| 구현 | 소스의 주요 함수 | 생성 코드에서 확인한 동작 |
| --- | --- | --- |
| IR 단순화 | `simplify_expr` | 상수 폴딩·조건 분기 제거·let 대입·단위 원소 제거·2의 거듭제곱 연산 축약 |
| 작은 함수 인라이닝 | `inline_pass` | 작은 직접 자기 재귀가 없는 함수를 펼치며, 상호 재귀를 자기 반복문으로 합치는 경우도 있음 |
| 결합 연산을 통한 비꼬리 재귀 변환 | `trmc_pass` | 숨은 누산기와 내부 함수를 추가해 add/mul/xor/or/and 재귀의 한 경로를 꼬리 호출로 변경 |
| 반복문 정규화 | `canonicalize_tail_loops_pass` | 여러 분기 끝의 자기 호출을 인자별 조건식과 단일 호출로 모음 |
| 공통식 제거·지역 슬롯 정리 | `cse_walk`, `compact_locals` | 반복 표현식을 let으로 묶고 사용하지 않는 슬롯 제거 |
| 레지스터·호출 최적화 | `setup_function_frame`, `emit_self_tail_call` | 사용 빈도로 지역 변수를 배치하고 자기 호출 인자를 가능한 경우 직접 갱신 |
| 기본 반환 경로의 프레임 생략 | `try_emit_shrink_wrap` | 피보나치의 단순 기본 반환에서 스택 프레임을 만들기 전에 반환 |
| 상수 나눗셈 | `emit_div_mod_const` | 2의 거듭제곱에는 시프트/마스크, 다른 상수에는 magic number와 `mulq` 사용 |
| AVX2 누산 | `analyze_avx2_loop`, `emit_avx2_loop` | add/xor/or/and/mul/min/max, Horner, shift-XOR, 최대 3개 누산기를 4원소씩 처리 |

벡터 인식은 인덱스가 매번 1씩 증가하고, 종료 조건이 루프 불변 경계와 비교되며, 누산기 사이의 의존성과 표현식 깊이가 제한을 만족할 때 적용된다. 입력 원소를 연속으로 읽는 경로는 벡터 반복 횟수를 제한하고 잔여 원소를 스칼라로 처리한다. 간접 인덱스는 실제 AVX2 gather 명령 대신 네 lane의 범위를 검사하고 스칼라로 읽어 벡터를 조립한다.

## 최적화를 끈 실험

원본을 보존한 채 SIMD, 재귀 변환, 인라이닝, 공통식 제거를 각각 끈 복사본을 만들었다. 동일한 v1 하네스, 7회 중앙값, 순차 측정이다. 아래는 원본과 해당 변형이 모두 정답을 낸 문제의 시간이다. 서로 독립적인 실험이므로 이득을 더하거나 곱해 전체 기여율로 해석하지 않는다.

| 문제 | 원본 | 해당 최적화 제거 | 해석 |
| --- | ---: | ---: | --- |
| 합계 | 0.529 µs | SIMD 제거 4.100 µs | 벡터화로 약 7.8배 |
| 곱 누산 | 3.671 µs | SIMD 제거 6.040 µs | 일반적인 벡터 u64 곱 경로는 정상 동작 |
| unsigned 최솟값 | 2.053 µs | SIMD 제거 8.239 µs | 벡터 min 누산 효과 |
| shift-XOR | 1.041 µs | SIMD 제거 6.167 µs | 순서를 보존한 점화식 벡터화로 약 5.9배 |
| 세 누산기 | 4.077 µs | SIMD 제거 10.126 µs | add/xor/mul을 함께 처리 |
| 비꼬리 합계 | 5.8 ns | 재귀 변환 제거 78.8 ns | 누산기 변환 뒤 벡터화까지 가능해짐 |
| 비꼬리 곱 | 13.9 ns | 재귀 변환 제거 77.8 ns | 곱셈에도 같은 변환이 적용됨 |
| 상호 재귀 | 7.086 µs | 인라이닝 제거 9.884 µs | 호출 구조 변환의 이득 |
| 보조 함수·공통식 | 6.016 µs | 인라이닝 제거 18.287 µs | 호출을 펼친 뒤 벡터화하는 효과가 큼 |
| 간접 인덱스 읽기 | 8.211 µs | SIMD 제거 **6.076 µs** | 스칼라 읽기·벡터 조립 비용 때문에 벡터 경로가 손해 |

`constant_div`는 7.366 µs, `constant_mod`는 8.625 µs다. 도달 가능한 어셈블리에 `divq`는 없고 `mulq`가 있다. 벡터 경로에서도 각 lane에 스칼라 magic 나눗셈을 적용하므로, YMM 명령이 있다고 나눗셈 자체가 병렬 벡터 명령으로 바뀐 것은 아니다.

`helper_cse`에서 공통식 제거를 끄면 6.016 → 6.176 µs로 차이가 작다. 생성 코드를 보면 스칼라 경로는 중복 곱셈을 제거하지만 벡터 분석의 `expand_lets_for_analysis`가 let을 다시 펼치고 벡터 생성기가 같은 계산을 재생성한다. CSE 제거 전후의 벡터 주 반복문과 수평 누산 코드는 동일했다. 길이 8192에서는 벡터 경로가 대부분을 처리하므로 이 작은 시간 차이를 CSE의 성능 이득으로 단정하지 않는다. 이 문제의 큰 이득은 인라이닝·벡터화 쪽에서 확인된다.

`non_associative_sub`는 재귀 호출이 남고 재귀 변환 제거 전후 약 79 ns로 같다. 결합법칙이 없는 뺄셈을 add/mul과 같은 방식으로 변환하지 않는지 확인하는 대조 문제다. 피보나치는 한 재귀 분기의 반복문 변환과 기본 반환 프레임 생략이 있으나 메모이제이션은 없으며 지수적인 계산 구조는 유지된다.

## 새 문제에서 드러난 오류

### Horner의 벡터 곱셈

`horner`는 초기값 17, 배수 31인 순서 의존 누산이다. 길이 4의 0 배열에서 정답은 `17 * 31^4 = 15699857`인데 결과는 0이다. 런타임 불변 배수를 쓰는 `horner_invariant`도 같은 입력에서 정답 17 대신 0을 반환한다.

벡터 Horner 경로는 배수의 네제곱을 `%ymm1`에 둔 뒤 `emit_ymm_mul64(..., y_b=1, ...)`을 사용한다. 이 특수 경로는 부분 곱을 계산하면서 `%ymm1`을 오른쪽으로 이동·덮어쓴 뒤 원래 배수의 하위 곱에도 같은 레지스터를 사용한다. 31의 네제곱처럼 상위 32비트가 0인 배수는 이 과정에서 0이 되어 누산기의 초기값을 잃는다. 일반 곱 누산이 통과하더라도 이 특수 경로는 별도 검사가 필요하다.

두 문제 모두 SIMD만 끈 변형에서는 통과한다. 원본의 실패 사례를 성능 비교 표에 넣지 않았다.

### 가변 나눗셈·나머지의 상위 lane 손실

길이 4에서 `variable_div`의 1 배열과 `variable_mod`의 `UINT64_MAX` 배열은 모두 정답 4 대신 2를 반환한다.

생성 코드가 lane 0·1의 결과를 원래 피제수가 있던 `%xmm9`에 저장한 다음, `%ymm9`에서 lane 2·3을 꺼낸다. 원래 상위 lane을 보존하기 전에 같은 레지스터를 덮어써 두 원소가 사라진다. 원래 `divmod`의 정답이 절반이 되는 현상도 같은 경로다. 세 문제 모두 SIMD 제거 변형에서 통과한다.

### 꼬리 호출 인자 보존 실패

`tail_rotation`은 인덱스와 세 상태 값을 함께 갱신한다. 세 상태는 서로 의존하므로 일반 꼬리 호출 인자 준비 경로를 사용한다. 생성 코드는 다음 인덱스를 `%r10`에 저장한 뒤 마지막 인자를 계산하면서 `%r10`을 이전 상태 값으로 덮어쓴다. 마지막에 이를 인덱스로 복사해 루프가 잘못 진행한다.

이 문제는 원본과 네 변형 모두 CPU 시간 초과로 실패한다. SIMD를 끈다고 해결되지 않는 스칼라 코드 생성 오류다. 다른 자기 꼬리 호출이 통과하더라도 동시에 갱신하는 인자의 값 보존을 별도로 검사해야 한다.

## 추가한 문제군

최적화 18개를 `v1/benchmarks/suite.tsv`의 정규 문제로 승격해 기본 평가가 총 26개를 사용한다. 이전 8개는 `suite-original.tsv`, 최적화 18개만은 `suite-optimizations.tsv`로 선택할 수 있다. `suite-extended.tsv`도 호환성을 위해 정규 suite와 같은 구성을 유지한다. v1의 언어·ABI와 v2의 문제군·프롬프트는 그대로다.

| 새 문제 | 확인하는 범위 |
| --- | --- |
| `product`, `unsigned_min` | 곱·unsigned min 누산과 항등원 |
| `horner`, `horner_invariant` | 순서 의존 점화식, 비영 초기값, 런타임 불변 배수 |
| `shift_xor`, `shift_xor_wide` | 점화식의 lane 재조합, 네 단계의 총 shift가 64 이상인 경우 |
| `constant_div`, `constant_mod` | 상수 나눗셈·나머지와 unsigned 경계값 |
| `variable_div`, `variable_mod` | 가변 분모, 0 처리, lane 보존 |
| `offset_window`, `indexed_gather` | 인접 원소·간접 인덱스 읽기, OOB=0, 벡터 잔여 처리 |
| `three_accumulators` | 네 인자와 세 종류의 누산기 |
| `tail_rotation` | 순환 의존성을 가진 꼬리 호출 인자 갱신 |
| `non_tail_product`, `non_associative_sub` | 재귀 변환이 가능한 곱과 같은 변환이 불가능한 뺄셈 |
| `helper_cse`, `variable_shift` | 인라이닝·중복 계산, 런타임 shift의 63 마스크 |

곱 문제는 각 원소를 홀수로 만들어 0이나 짝수의 반복 곱 때문에 결과가 쉽게 0으로 퇴화하는 것을 줄였다. Horner와 shift-XOR는 초기값을 0 이외의 값으로 잡아 벡터 경로가 초기값을 잃는 오류도 검출한다. 비꼬리 문제는 참조 실행기의 깊이 한도를 지키도록 길이 32를 사용한다.

`v1/tests/test_optimizations.py`는 독립적인 Python 정답을 사용해 빈 입력, 4원소·8원소 폭의 전후 길이, 최대 정수·최상위 비트·0·큰 shift·난수 등 총 1,660개 입력을 대조한다. 현재 베이스라인은 이 검사와 확장 하네스 문제 26개를 모두 통과한다.

## 실행과 산출물

```sh
make v1 test-optimizations

# 추가 18개만 평가
./build/v1/compbench --compiler ./build/res/v1/gemini-4-argon-high \
  --suite v1/benchmarks/suite-optimizations.tsv --output build/v1/optimizations.json

# 정규 26개 평가
./build/v1/compbench --compiler ./build/res/v1/gemini-4-argon-high \
  --output build/v1/results.json

# 원본 스냅샷 빌드, 베이스라인 검증, 최적화 제거 실험
python3 scripts/analyze_argon_high.py
```

`build/analysis/argon-high/summary.json`에 원본·AST·suite 해시, 정확성·시간, 도달 가능한 어셈블리 통계와 인식한 누산 종류가 있다. 하위 디렉터리에는 분석용 소스와 문제별 어셈블리·trace가 있다. trace를 추가한 원본 버전의 어셈블리는 추적 없는 원본 컴파일러와 26/26 바이트 단위로 일치한다. 원본 제출 소스는 수정하지 않았다.

기존 측정값에 실패 배율 1.0을 적용한 점수는 다음과 같다. 통과한 문제의 실측 배율과 실패한 문제의 1.0을 전체 26개로 기하평균했다.
