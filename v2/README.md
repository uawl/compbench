# compbench v2 — 배열 값 지원

순수 재귀 AST를 x86-64/AVX2 어셈블리로 최적화 컴파일하는 **C 프로그램**을 평가하는 하네스의 **v2 — 배열 값(재귀 리스트) 지원 버전**이다. 하네스, AST 파서, 참조 실행기, 비교용 컴파일러 모두 C로 구현했다. Python은 테스트·평가 자동화·프롬프트 생성·그래프 렌더링에 사용한다.

모든 명령은 저장소 루트에서 실행한다. 버전 간 차이와 평가·그래프 명령은 [루트 README](../README.md)에 있다.

## 실행

Linux x86-64, AVX2를 사용할 수 있는 CPU/OS, C11 컴파일러와 GNU 호환 어셈블러/링커가 필요하다. 외부 라이브러리 설치는 필요 없다.

```sh
make v2
make demo-v2
make test-v2
```

`make demo-v2`는 비교용 컴파일러를 제출물로 사용해 전체 흐름을 실행하고 `build/v2/results.json`에 결과를 저장한다. 자기 자신과의 비교이므로 속도 배율은 대략 1이다. 측정 잡음에 따라 달라진다.

코드 생성기 stub을 구현한 제출물은 고정 파서와 진입 코드를 함께 빌드한다:

```sh
cc -std=c11 -O2 -Iv2/include v2/src/baseline.c v2/src/ast.c solution.c -o build/v2/solution
./build/v2/compbench --compiler ./build/v2/solution --output build/v2/results.json
```

작동하는 제출물 예제는 `v2/src/baseline.c`와 `v2/src/codegen.c`다. 비교용 컴파일러는 외부 C 컴파일러에 코드 생성을 맡기지 않고 직접 스칼라 어셈블리를 생성한다. 꼬리 위치의 함수 호출은 상호 재귀를 포함해 점프로 변환한다.

## 제출 규약

하네스는 제출 실행 파일을 다음 두 인자로 호출한다:

```text
compiler INPUT.ast OUTPUT.s
```

입력과 출력 경로는 절대 경로로 전달한다. 성공 시 종료 코드 0과 GNU assembler 형식의 어셈블리 파일을 생성한다. 진단 메시지는 stdout/stderr에 출력할 수 있다.

생성된 파일은 PIC 공유 라이브러리로 링크할 수 있어야 하며 다음 심볼을 정의해야 한다:

```c
uint64_t bench_entry(const uint64_t *xs, uint64_t n, CbArena *arena);
```

Linux System V AMD64 호출 규약을 준수한다. `xs`는 읽기 전용 배열이고 `n`은 원소 수다. 길이 0일 때는 포인터를 역참조하면 안 된다. 함수는 같은 입력에 같은 결과를 반환하고 호출 사이에 계산 상태를 남기지 않아야 한다. 생성 코드는 독립적으로 계산하며 참조 실행기나 외부 실행 파일을 호출하지 않는다. 스칼라 코드와 AVX2 코드 모두 평가한다.

진입 함수 타입이 `CB_U64`면 반환값은 정수, `CB_LIST`면 `CbList *`를 `uint64_t`로 표현한 값이다. `CbList`는 `head`와 `tail`을 담은 16바이트 셀이며 NULL은 빈 리스트다. 새 리스트 셀은 호출자가 제공한 `CbArena`에 만든다. v1은 별도의 2인자 ABI를 사용하며 v2는 이 3인자 ABI를 사용한다.

`arena->input`은 `xs`의 같은 원소를 순서대로 담은 읽기 전용 리스트다. 호출마다 `used`와 `failed`를 0으로 초기화하고, `nodes`는 1,048,576개 셀 공간을 제공한다. 새 셀은 `nodes[used++]`에 초기화하며 한 번 만든 셀은 변경하지 않는다. 입력과 이미 만든 리스트의 꼬리는 공유할 수 있다. 반환 리스트의 셀은 입력 리스트 또는 사용한 arena 영역에 속해야 한다. 노드 저장 영역과 결과의 유효 기간은 다음 호출 전까지다. 생성 코드는 `nodes`, `capacity`, `input`을 변경하지 않는다. 공간이 부족하면 범위 밖에 쓰지 않고 `failed = 1`을 표시한다. 정상 문제는 베이스라인도 이 공간 안에서 계산할 수 있도록 구성한다.

컴파일러의 C 소스 빌드는 별도로 수행한다. 하네스는 주어진 실행 파일이 C로 작성되었는지나 외부 도구 사용 여부를 검사하지 않는다.

## AST와 의미

입력은 S-expression으로 직렬화한 AST다. 변수 바인딩은 어휘적 범위를 가지며 `let`은 재할당이 아니다. 앞에 선언되지 않은 함수 호출과 상호 재귀도 허용한다.

```text
(program
  (fn main () (call sum 0 0))
  (fn sum (i acc)
    (if (eq i len) acc
      (call sum (add i 1) (add acc (get i))))))
```

타입은 `u64`와 불변 `list<u64>`다. 배열 값은 빈 리스트와 `cons`·`head`·`tail`을 사용하는 재귀 리스트 형태로 표현한다. 함수 인자, 바인딩, 중간값과 반환값에 두 타입을 사용할 수 있다. 입력은 하나의 배열이며 `input`으로 같은 원소의 리스트 값을 얻는다. 여러 리스트 값을 만들어 전달·반환·공유할 수 있으나 리스트 원소는 `u64`이며 중첩 리스트는 없다.

고정 파서는 프로그램 전체에서 표현식·인자·반환 타입을 추론하며 상호 재귀도 처리한다. 조건은 `u64`, `if` 양쪽 분기는 같은 타입이어야 한다. 산술과 비교는 `u64`에만 적용한다. 해결되지 않은 타입 변수는 `u64`로 결정한다. `CbExpr.type`, `CbFunction.return_type`, `CbFunction.local_types`에 결과를 기록하므로 제출물은 타입 추론을 구현하지 않는다.

| AST | 의미 |
| --- | --- |
| `123`, `0xffffffffffffffff` | 10진수 또는 16진수 `u64` 리터럴 |
| `name` | 함수 인자 또는 `let` 변수 |
| `len` | 입력 배열의 길이 |
| `(get i)` | `xs[i]`; `i >= len`이면 0 |
| `input`, `nil` | 입력 원소를 순서대로 담은 리스트, 빈 리스트 |
| `(cons x xs)` | `u64` 원소 `x`를 리스트 `xs` 앞에 붙인 새 리스트; 기존 리스트는 보존 |
| `(head xs)` | 첫 원소; 빈 리스트이면 0 |
| `(tail xs)` | 첫 원소를 제외한 리스트; 빈 리스트이면 `nil` |
| `(is_nil xs)` | 빈 리스트이면 1, 아니면 0 |
| `(let name value body)` | 값을 바인딩하고 `body` 평가 |
| `(if condition yes no)` | 조건이 0이 아니면 `yes`, 아니면 `no`; 선택한 분기만 평가 |
| `(call function arg ...)` | 순수 함수 호출 |
| `(add a b)`, `(sub a b)`, `(mul a b)` | modulo 2^64 산술 |
| `(div a b)`, `(mod a b)` | unsigned 몫/나머지; `b == 0`이면 둘 다 0 |
| `(and a b)`, `(or a b)`, `(xor a b)` | 비트 연산 |
| `(shl a b)`, `(shr a b)` | 이동량 `b & 63`; 오른쪽 이동은 논리 시프트 |
| `(eq a b)`, `(ne a b)`, `(lt a b)`, `(le a b)`, `(gt a b)`, `(ge a b)` | unsigned 비교; 결과 0 또는 1 |

`;`부터 줄 끝까지는 주석이다. 함수 이름과 바인딩은 영문자/밑줄로 시작하고 영문자·숫자·밑줄을 포함한다. `len`, `input`, `nil`은 바인딩 이름으로 사용할 수 없다. `main`은 인자가 없어야 한다.

리스트를 만드는 예:

```text
(program
  (fn main () (call reverse input nil))
  (fn reverse (xs acc)
    (if (is_nil xs) acc
      (call reverse (tail xs) (cons (head xs) acc)))))
```

참조 실행기의 `cb_eval_result()`는 정수 또는 원소 전체를 복사한 리스트 결과를 반환한다. 호출자는 `cb_result_free()`로 해제한다. 기존 `cb_eval()`은 정수 반환 함수용 래퍼다.

**확정한 규칙:** unsigned 64비트 정수와 배열, 재귀, 0으로 나눈 몫과 나머지는 0이다. 범위 밖 배열 읽기, wraparound, 시프트 이동량 규칙은 첫 버전을 실행하기 위해 명시한 선택이므로 이후 명세 변경 시 참조 실행기와 테스트도 함께 수정한다. 어떤 예외도 C의 undefined behavior로 해석하지 않는다. 예를 들어 `x / x`는 `x == 0`에서 0이므로 무조건 1로 치환할 수 없다.

v2 파서 한도는 함수 64개, 함수당 인자 4개·지역 바인딩 128개, 전체 노드 4096개, AST 중첩 256단계, 파일 1 MiB다. 참조 실행기는 입력당 2천만 노드 평가, 비꼬리 평가 깊이 256단계, 생성 리스트 셀 1,048,576개를 허용한다. 입력 리스트는 별도로 구성한다. 꼬리 재귀는 참조 실행기에서도 반복 처리한다. 종료하지 않는 AST나 이 한도를 넘는 문제는 정상 평가 문제로 사용하지 않는다.

## 난이도와 문제 추가

`v2/benchmarks/suite.tsv`는 다음 세 열을 사용한다. 파일 경로는 manifest 기준이며 공백을 포함하지 않는다.

```text
# 난이도  성능측정용 배열 길이  AST 경로
1 8192 sum.ast
```

| 난이도 | 기본 문제 | 평가하는 구조 |
| --- | --- | --- |
| 1 | `sum`, `unsigned_max` | 직접적인 꼬리 재귀와 unsigned 값 |
| 2 | `conditional_sum`, `divmod` | 조건부 계산, 여러 누산기, 나눗셈의 0 처리 |
| 3 | `mutual_recursion`, `helper_mix` | 상호 재귀, 보조 함수 분석 |
| 4 | `non_tail_sum`, `fibonacci` | 비꼬리 재귀와 여러 재귀 호출 |

리스트 문제 6개도 포함한다: `list_sum`, `list_reverse`, `list_map`, `list_sharing`, `list_zip`, `list_map_recursive`. 리스트 인자·반환, 재귀 변환, 원본 보존과 꼬리 공유, 4개 혼합 타입 인자, 비꼬리 리스트 생성을 검사한다. 전체 기본 문제는 14개다.

새 AST와 manifest 항목을 추가하면 하네스가 참조 결과를 자동 계산한다. 다른 문제군은 `--suite PATH`로 선택한다. manifest의 난이도는 필수 최적화나 점수 가중치를 강제하지 않고, 문제 분류와 정확성 입력 길이에 사용한다.

## 검증과 성능 측정

정확성 입력은 길이 0, 1, SIMD 처리 폭과 그 배수 전후, 최대 129개 원소를 포함한다. 비꼬리 재귀 문제인 4단계는 최대 32개로 제한한다. 각 길이에 0, 1, `UINT64_MAX`, 최상위 비트가 켜진 값, 경계값 혼합, 증가 수열, 난수, 0이 섞인 난수를 사용한다. 추가 난수 길이 24개와 성능 측정에 쓰는 입력 4개도 검사한다. 순서대로 한 번, 역순으로 한 번 호출한다. 기본 문제의 검사 횟수는 각각 392회 또는 280회다.

입력 배열은 읽기 전용 메모리에 복사하고 마지막 원소 바로 뒤에 접근 금지 페이지를 둔다. 길이 0인 배열도 역참조를 검출한다. 범위 밖 읽기는 의미상 0이므로, 생성 코드가 실제로 잘못된 주소를 읽으면 실패한다. 배열 앞쪽은 페이지 정렬 때문에 일부 여유 공간이 있을 수 있어 모든 범위 밖 접근을 하드웨어로 검출하는 것은 아니다.

입력 리스트도 읽기 전용 메모리에 구성하고, 새 셀용 arena 양쪽에 접근 금지 페이지를 둔다. 리스트 반환은 포인터가 아니라 길이와 원소 전체로 비교한다. 입력/arena 밖의 셀 포인터, 잘못된 원소, 짧거나 긴 리스트, 순환 꼬리, 메모리 공간 부족을 실패로 처리한다. JSON 형식의 `schema_version`은 2이며, 벤치마크 버전은 별도 `benchmark_version: "v2"`로 기록한다.

참조 결과 계산과 컴파일은 측정 시간에서 제외한다. 같은 입력으로 제출 코드와 스칼라 비교 코드를 검사한 뒤 한 프로세스에서 같은 CPU에 고정해 번갈아 측정한다. CPU 고정이 허용되지 않으면 그대로 진행한다. 4개 입력을 순환하며 워밍업/호출 횟수 보정을 수행하고, 7회 측정 중앙값을 `ns/call`로 기록한다. 작은 함수에는 호출과 측정 루프 비용도 포함된다. 입력 리스트 구성과 결과 비교는 측정 밖에서 수행하고, 리스트 생성 계산은 측정에 포함한다. arena 저장 공간은 미리 확보하며 호출마다 사용량·실패 플래그를 초기화하는 비용은 측정에 포함한다.

성공한 문제의 배율은 `baseline_ns / candidate_ns`, 실패한 문제의 배율은 **1.0**으로 계산한다. 전체 점수는 이를 전체 문제 수로 기하평균하며, 실패한 문제도 분모에 포함한다. 성공한 문제의 배율이 1 미만이면 그대로 반영하고 전부 실패하면 1.0이다. 실패 상태·통과 개수·오류 메시지도 함께 기록한다. 실행 시간 잡음은 남아 있으므로 모델 간 최종 비교에는 고정된 전용 환경이 필요하다.

제출 컴파일러는 10초, 어셈블/링크는 15초, 생성 코드 검사·측정은 문제당 10초의 wall-clock 제한을 적용한다. 자식 프로세스는 메모리 1 GiB 및 CPU 시간 제한을 적용하고, 시간 초과 시 프로세스 그룹을 종료한다. 크래시와 오답은 해당 문제의 실패로 기록하며 다른 문제는 계속 실행한다. 이 프로세스 격리는 오류 처리를 위한 것으로 악의적인 제출물을 위한 보안 샌드박스는 아니다. AVX2 사용 가능 여부는 검사하지만, AVX2보다 새로운 명령어 사용을 차단하는 ISA 검사는 아직 포함하지 않는다.

```sh
./build/v2/compbench --compiler ./build/v2/solution \
  --suite v2/benchmarks/suite.tsv --seed 2026 \
  --output build/v2/results.json --keep-artifacts
```

`--keep-artifacts`는 생성 어셈블리, 공유 라이브러리, 컴파일 로그를 임시 디렉터리에 보존한다. 기본은 실행 후 제거한다. `--cc PATH`로 어셈블/링크에 사용할 실행 파일을 지정한다. 종료 코드는 전체 통과 0, 문제 실패 1, 설정/결과 파일 오류 2다.

현재 문제와 시드는 공개 예제다. 최종 모델 평가를 위한 비공개 AST·변형 문제·실행 환경 격리는 별도로 구성해야 한다.

## 주요 파일

- `v2/src/harness.c`: 제출 컴파일러 호출, 격리 실행, 정확성 검사, 측정, JSON 결과.
- `v2/src/ast.c`: AST 파싱·검증과 순수 재귀 참조 실행기.
- `v2/src/codegen.c`: 스칼라 비교용 코드 생성기.
- `v2/include/ast.h`: 제출물에서 재사용할 수 있는 AST API.
- `v2/tests/test_ast.c`: 정수 의미, 바인딩, 재귀, 잘못된 입력 검증.
- `v2/tests/test_harness.py`: 독립적인 정수 계산과 생성 코드 비교, 전체 실행, 실패/시간 초과 처리 검증.

## 모델에게 전달할 프롬프트

[`prompts/compiler.md`](prompts/compiler.md)를 그대로 전달한다. 코드 stub, 측정하는 작업 종류의 개요, 연산 의미와 출력 규약, 코드 생성기에 필요한 AST 구조체·필드, 베이스라인 codegen 전체를 포함한다. 개별 벤치마크의 AST·소스·상수·구체적인 구현과 하네스의 측정 절차는 포함하지 않는다. 모델은 파서를 수정하지 않고 `solution.c`의 `cb_emit_assembly()`를 구현해 C 소스 코드만 출력한다.

모델의 제출물은 다음과 같이 빌드하고 평가한다. 평가용 `v2/src/codegen.c`를 이 빌드에 링크하지 않는다.

```sh
cc -std=c11 -O2 -Wall -Wextra -Iv2/include \
  v2/src/baseline.c v2/src/ast.c solution.c -o build/v2/solution
./build/v2/compbench --compiler ./build/v2/solution --output build/v2/solution-results.json
```

프롬프트 본문을 수정할 때는 `v2/prompts/compiler.template.md`를 수정한 뒤 `make prompt-v2`로 생성한다. AST 헤더와 베이스라인 codegen은 현재 저장소 파일에서 그대로 삽입되므로 수동 복사할 필요가 없다. `python3 scripts/build_prompt.py --version v2 --check`로 프롬프트가 현재 코드와 일치하는지 확인할 수 있다.
